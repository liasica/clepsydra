# 需求性质标签设计

日期：2026-08-11

## 背景与目标

需求已有「项目」（Project）标签用于归属分类，但缺少区分**需求性质**（如新功能、缺陷修复、优化、重构等）的维度。本设计引入独立的「标签」（Tag）实体：

- 标签统一管理：超管在「标签管理」页维护（增删改查），用户不可自行指定颜色
- 颜色由后端根据标签名称自动生成并固化存库
- 需求可打多个性质标签，与项目标签并存、互不影响
- 仅在需求管理内展示与筛选（列表、详情、表单），账单明细不加

明确不做（YAGNI）：

- 标签不做 remark 备注字段（性质标签名称自解释）
- 不做账单明细的标签展示
- 不做前端创建时的颜色预览（颜色由后端生成，创建后即可见）
- 不做标签软删除

## 数据模型

新增 `internal/ent/schema/tag.go`，形态与 Project 平行：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 标签名，必填，唯一 |
| `color` | string | 十六进制色值（如 `#3b82f6`），创建时由后端根据名称生成并固化，之后改名不重算，接口不接受外部传入 |
| `created_at` / `updated_at` | time | 时间戳，跟随现有惯例 |

- 不使用 `SoftDeleteMixin`：删除即物理删除，与需求的关联由中间表外键级联清除（与 Project 一致）
- `Tag` 与 `Demand` 建多对多 edge：`Tag` 定义 `edge.To("demands")`，`Demand` 定义 `edge.From("tags")`，自动生成中间表 `tag_demands`
- 需求软删除后不主动清理关联，跟随项目标签的既有处理方式

## 颜色生成算法

位于 service 层，创建标签时调用：

1. 对标签名做 FNV-1a hash
2. `hue = hash % 360`，固定饱和度 65%、亮度 50%
3. HSL 转换为十六进制色值（如 `#8a2be2`）存库

特性：

- **确定性**：同名必得同色
- **固化**：仅创建时计算一次存库；改名不重算；将来即使调整算法，已有标签颜色不受影响

## 后端接口

### 标签 CRUD

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `GET /tags` | 所有登录用户 | 标签列表（含每个标签的关联需求数 `demand_count`），供管理页、下拉与筛选使用 |
| `POST /tags` | 超管 | 创建标签，仅接受 `name`，颜色由后端生成；重名返回 400 |
| `PUT /tags/:id` | 超管 | 改名（颜色不变）；重名返回 400 |
| `DELETE /tags/:id` | 超管 | 物理删除并解除全部需求关联；不存在返回 404 |

新增 `internal/service/tag.go` 与 `internal/api/handler/tag.go`，标签的创建/更新/删除记入审计日志（跟随现有 `Audit` 惯例）。

### 需求接口变更

完全复刻项目标签的模式：

- `POST /demands`：请求体新增 `tag_ids []int`（可选），创建时建立关联；含不存在的标签 ID 返回 400
- `PUT /demands/:id/tags`（新增，登录即可）：全量覆盖式更新需求的标签关联（传空数组即清空），不受需求状态限制——标签是归类元数据，不影响人天与账单金额
- `GET /demands`、`GET /demands/:id`：查询时预加载标签（ent `WithTags`，响应中体现在 `edges.tags`）；列表接口新增查询参数 `tag_id`（按单个标签筛选），与 `project_id` 可叠加
- service 层 `Demand.Create` 增加 `tagIDs []int` 入参；新增 `Demand.UpdateTags` 方法

## 前端（dashboard/apps/web-antdv-next）

1. **标签管理页** `src/views/tags/`：仅超管菜单可见，表格（名称、颜色色块预览、关联需求数、创建时间）+ 新建/编辑弹窗（只有名称输入框）+ 删除确认，文案提示「该标签已关联 N 个需求，删除后仅解除关联，不影响需求本身」
2. **需求新建/编辑表单**：新增标签多选下拉（选项来自 `GET /tags`）；创建走 `tag_ids`，编辑模式保存时调用 `PUT /demands/:id/tags`（跟随项目标签「未变化时不重写关联」的既有优化）
3. **需求列表**：每行标签列以彩色 Tag 展示（antdv `Tag` 的 `:color` 直接使用 hex 值）；筛选区新增标签下拉，选中后传 `tag_id`
4. **需求详情**：基本信息区展示性质标签，新增 `DemandTagsDialog` 编辑入口（仿照现有 `DemandProjectsDialog`，任何状态可编辑）
5. API 封装新增 `src/api/tag.ts`，跟随现有结构

## 错误处理

- 标签重名：数据库唯一约束 + service 层友好报错「标签名称已存在」
- 需求关联不存在的标签 ID：返回 400「标签不存在」
- 删除/更新不存在的标签：404

## 测试

- service 层：标签 CRUD、颜色生成确定性（同名同色）、改名不变色、重名冲突、删除解除关联；需求创建/更新携带 tag_ids 的关联读写、无效 ID 校验、`tag_id` 筛选（含与 `project_id` 叠加）
- handler 层：权限（非超管写标签返回 403）、请求体解析（`color` 字段不可外部传入）
- 前端：跟随现有测试惯例补充关键组件测试
